## What Is Correct

The HTTP write-block middleware is placed before the API router, WebSocket route, and static mounts in `backend/app/main.py`, and it blocks `POST`, `PUT`, `DELETE`, and `PATCH` before route dependencies or handlers run. That covers API routes and mounted static sub-app paths for HTTP writes. The route-walk regression test covers `APIRoute` write endpoints; mounted static routes are not included in that walk, but the middleware itself still applies to them.

The WebSocket endpoint only accepts inbound `ping` messages and otherwise relays logger daemon updates to clients. I did not find an inbound WebSocket command path that can mutate state.

The `require_admin` bypass broadens admin-only reads in public mode. I did not find an admin-only GET whose handler commits to the database or performs a hardware write because of this bypass. Existing admin-only GETs do perform read IPC and external fetches; that is a widened read/availability surface, but not a state-change path in this phase.

`PublicRelayDriver` implements the current `StationDriver` ABC: `connect`, `disconnect`, `poll`, `detect_hardware`, `connected`, `station_name`, and `capabilities`. It opens no serial port or socket and `_create_driver` wires the `public_relay` type to that implementation.

## Blockers

1. `PUT /api/config` can mutate `station_driver_type` without invalidating the public-mode cache.

   `backend/app/api/config.py:227` accepts arbitrary config updates and writes each `update.key` to `station_config`, including `station_driver_type`, then commits at `backend/app/api/config.py:267`. This path does not call `public_mode.invalidate_cache()`. The PR invalidates only `POST /api/setup/complete` and `POST /api/setup/reconnect` in `backend/app/api/setup.py:167` and `backend/app/api/setup.py:197`.

   That leaves a stale security boundary for up to 30 seconds after an operator or API client flips the driver type via `/api/config`. If the process has cached `False` and `/api/config` changes `station_driver_type` to `public_relay`, subsequent write requests can still pass through the middleware until the TTL expires. Conversely, a cached `True` can keep private-mode writes blocked briefly after switching away. For this load-bearing gate, every writer of `station_driver_type` must invalidate the cache in the same commit path, and there should be a regression test for the `/api/config` mutation path.

## What Needs Attention

The 30 second cache is process-local. If Kanfei is ever run with multiple uvicorn workers, invalidating in one worker will not invalidate the others. I did not find evidence that this deployment uses multiple workers, so I am not making this a blocker for Phase 1, but it is part of the security-boundary assumptions and should stay explicit.

`GET /api/station` already has an auto-sync side effect when a real station clock drift exceeds the threshold. That endpoint is not admin-only, so it is not introduced by the `require_admin` bypass. In public relay mode the driver should not expose real hardware clock sync, but this existing GET side effect is worth keeping in mind when defining "read-only" globally.

## Bloat / Non-Functional

None.

## Recommendations

Invalidate public-mode cache from `backend/app/api/config.py` when any accepted update has `key == "station_driver_type"`. Do it after the DB commit succeeds so the next request re-reads committed state. Add a focused test that primes `is_public_mode()` to `False`, updates `station_driver_type` through `/api/config`, then asserts the next write is blocked immediately.

## Bottom Line

Request changes. The middleware shape, WebSocket assessment, `require_admin` bypass behavior, and driver ABC conformance look sound for Phase 1, but the `/api/config` cache invalidation gap leaves the public-mode write gate stale after one legitimate driver-type mutation path.
