## What Is Correct

- Saved layouts still win over persona defaults in the local load path: `loadLayout()` passes the persona default only as `parseLayout()`'s fallback, so a valid stored `ui_dashboard_layout` is returned unchanged.
- `loadLayout()` reads `ui_persona` synchronously from `localStorage` via `readUIPref()` and does not import or call PersonaContext outside a component.
- The mount-time dashboard reconcile effect intentionally has an empty dependency array, so a persona switch after mount cannot re-run that reconcile and overwrite an existing saved layout.
- `DEFAULT_LAYOUT` remains exported as `WEATHER_NERD_LAYOUT`, preserving the all-tiles pre-persona default shape and object identity.
- `App.tsx` wraps `DashboardLayoutProvider` inside `PersonaProvider`, so `usePersona()` in the dashboard provider is safe.
- `parseLayout()`'s new `fallback` parameter is used in each v2 failure path: empty raw value, schema-version mismatch, zero valid tiles, and JSON parse failure.

## Blockers

1. `frontend/src/dashboard/DashboardLayoutContext.tsx:238` leaves a fresh browser on the wrong default when the persona exists only in backend prefs. On a new browser with no `localStorage.ui_persona` and no saved `ui_dashboard_layout`, `loadLayout()` seeds the dashboard with the local default persona (`everyday`). `syncUIPrefs()` can then return backend `ui_persona=agriculture` or `weather_nerd`, and `PersonaProvider` updates the visible persona, but this dashboard effect does nothing when `prefs[PREF_KEY]` is empty. Because the effect also intentionally does not depend on `persona`, the dashboard remains the initial everyday layout while the rest of the UI reflects the synced persona. That breaks the PR's first-visit persona-default guarantee for the backend-backed preference path added in the earlier persona plumbing. Fix without violating the no-clobber rule by using the synced persona from `prefs.ui_persona` during the mount reconcile only when there is no saved dashboard layout; keep the saved-layout branch exactly as-is.

- Keep the effect independent of later `persona` changes. The needed fix is a mount-time backend preference reconciliation for the no-saved-layout case, not a general persona dependency.
