## What Is Correct

The change correctly identifies the FastAPI 0.141 `_IncludedRouter` shape as a real risk for the two route-walk tests. Centralizing the route enumeration helper is also the right place to fix it; both affected tests need the same request-time route surface.

The `_PrefixedRoute` wrapper's minimal surface is appropriate for the current call sites. They only read `path` and `methods`, and keeping the wrapper narrow reduces the chance it gets mistaken for a full `APIRoute` replacement.

I verified the existing checkout on FastAPI 0.135.1:

- `cd backend && python3 -m pytest ../tests/backend/test_ingest_endpoints.py::TestMiddlewareAllowlist::test_allowlist_matches_route_paths_exactly ../tests/backend/test_public_mode_gates.py::TestNoWriteEndpointEscapesTheGate::test_every_write_route_returns_403_in_public_mode -q`
- Result: 2 passed.

## Blockers

1. `tests/backend/_route_walk.py:55`-`tests/backend/_route_walk.py:61` double-prefixes nested `_IncludedRouter` routes that already include their own router prefix, so the write-gate test can exercise nonexistent paths and still pass with 403.

   I reproduced this against FastAPI 0.141.1 in a disposable venv with a nested router shaped like Kanfei's `/api` router plus a child router with its own prefix:

   ```text
   _IncludedRouter orig.prefix=/api
     APIRoute path=/api/direct
     _IncludedRouter orig.prefix=/leaf
       APIRoute path=/leaf/write
   walked [('/api/leaf/leaf/write', ['POST'])]
   ```

   The request-time route is `/api/leaf/write`, but the walker yields `/api/leaf/leaf/write` because it accumulates `prefix + original.prefix` before descending, then also prefixes an `APIRoute.path` that already contains the child router prefix. Kanfei has the same pattern for prefixed child routers such as `backup`, `auth`, `spray`, `map`, `mute`, and others. The current CI can stay green because `TestNoWriteEndpointEscapesTheGate` only checks for a 403; the public-mode middleware returns 403 for arbitrary non-allowlisted write paths before routing, so a nonexistent doubled path can still satisfy the assertion. That preserves the silent-defang risk this commit is meant to remove.

   The helper needs to prove it emits exact request-time paths for both FastAPI shapes, including at least one nested router whose child router has a non-empty prefix. A direct unit test with a synthetic FastAPI 0.141-style tree is enough if pinning two dependency versions in CI is not practical.

## What Needs Attention

The return annotation `Iterator[APIRoute]` is now technically inaccurate because `_PrefixedRoute` is intentionally not an `APIRoute`. That is not a blocker for these tests, but a small protocol type with `path` and `methods` would better document the real contract if this helper stays.

## Bloat / Non-Functional

The long helper docstring is more narrative than test support code normally needs, but it documents a version-specific CI failure and a load-bearing invariant. I would not block on it.

## Recommendations

Adjust the `_IncludedRouter` prefix accumulation so child APIRoute paths are not double-counted. Then add a regression check that would fail for `/api/leaf/leaf/write` and pass only for `/api/leaf/write`.

## Bottom Line

Revise before merge. The follow-up fixes the empty-route failure mode for unprefixed child routes like ingest, but it still yields wrong paths for nested routers with their own prefixes, leaving the main write-route regression guard able to pass without hitting the real endpoints.
