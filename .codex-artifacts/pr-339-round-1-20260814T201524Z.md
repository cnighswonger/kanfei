## What Is Correct

The two new public write holes are narrowly scoped and independently authenticated. `backend/app/main.py:321` allowlists exactly `/api/ingest/reading` and `/api/ingest/config`, and the registered FastAPI route paths are exactly those two strings. Because the middleware compares `request.url.path` before route dispatch, a non-allowlisted variant such as a trailing-slash path is denied in public mode rather than accidentally routed around the gate.

The bearer path is structurally correct for this phase. `backend/app/api/ingest.py:79` refuses an unconfigured droplet before credential comparison, and `backend/app/api/ingest.py:91` uses `hmac.compare_digest` for the actual secret comparison. Missing/non-bearer credentials and wrong credentials do not reach IPC. The 503 unconfigured versus 401 bad credentials split is an intentional operator-diagnostics leak of setup state, not a useful secret leak once the endpoint is already public.

The daemon guard is in the right place. `_require_public_relay()` refuses absent or non-`PublicRelayDriver` drivers before calling `push_snapshot()` or `push_config()`, so a misrouted IPC command cannot mutate a normal station driver. IPC handler exceptions are wrapped by the IPC server into `{"ok": false, "error": ...}` responses rather than killing the daemon.

Secret masking covers the public droplet read-bypass path. `backend/app/api/config.py:34` includes `public_mode_ingest_secret` in `_SECRET_KEYS`, and `backend/app/api/config.py:220` applies that mask in `GET /api/config`. I specifically tested `station_driver_type=public_relay` with no auth and a stored ingest secret; the response returned `abcd********************`, not the raw value.

## Blockers

None.

## What Needs Attention

Non-blocking: `backend/logger_main.py:2230` through `backend/logger_main.py:2237` only validates that `snapshot` is a dict after the `or {}` coercion and then constructs `SensorSnapshot` without field-level type validation. An authenticated sender can push values like `{"outside_temp": "bad"}` or `{"extra": []}` and receive success; the bad buffered snapshot can then make the poller log repeated processing errors until a valid snapshot replaces it. That is not an unauthenticated state-change path and does not crash the daemon process, so I would not block Phase 2 on it, but Phase 3 should either send only known-good typed payloads from the private relay or add a shared schema/normalizer before buffering.

Rate limiting is absent, as expected for Phase 2. With the bearer secret and intended nginx IP allowlist, this is defensible as a documented Phase 3/Phase 5 hardening item rather than a Phase 2 blocker. It should still be tracked because these endpoints are public-facing and each authenticated request can hit the DB for the secret and the daemon over IPC.

## Bloat / Non-Functional

None. The implementation is small and localized to the new ingest router, two middleware allowlist entries, two IPC command handlers, config masking, and focused tests.

## Recommendations

Add one future test for the exact public-mode masking case already verified manually here: unauthenticated `GET /api/config` with `station_driver_type=public_relay` and a stored ingest secret must return a masked value.

When Phase 3 adds the private-side relay sender, keep the `SensorSnapshot` wire schema shared or generated from one place. That will make the current daemon-side permissiveness less risky without duplicating every field by hand.

## Bottom Line

Approved. The PR preserves the Phase 1 read-only boundary while adding only the two intended bearer-gated write endpoints. I found no path that lets an unauthenticated caller change droplet state or read the ingest secret.
