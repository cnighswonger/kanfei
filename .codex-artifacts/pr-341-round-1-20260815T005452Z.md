## What Is Correct

- `tests/backend/test_public_relay_sender.py:332` exercises the real regression class for readings: it captures the sender's actual HTTP JSON body, passes it through `IngestReadingPayload(**body).model_dump()`, wraps it under the IPC `snapshot` key, then applies the daemon-side `SensorSnapshot` field filter. If the sender re-wraps as `{"snapshot": {...}}`, `cleaned` becomes empty and the test fails before constructing the snapshot. The identity test similarly catches a re-wrap by requiring `station_name` to remain top-level after endpoint parsing.
- `frontend/src/App.tsx:35` places `useFeatureFlags()` inside the active `FeatureFlagsProvider` tree (`frontend/src/App.tsx:135`), and the bypass only fires after flags load and `publicModeActive` is true. Private stations keep `publicModeActive: false`, so unauthenticated users still redirect to `/login`.
- `frontend/src/components/setup/StepLocation.tsx` moving unconditionally from `tile.openstreetmap.org` to Carto is acceptable. It changes the tile provider for private stations but preserves the OSM-derived visual intent and avoids carrying two provider policies through a shared setup/settings component.
- Cherry-pick cleanliness checks passed: each PR commit has the same stable patch-id as its corresponding `deb` commit (`d705f20`=`8132cde`, `ae7e4c6`=`64ca46e`, `1b7662e`=`d8ef014`, `d115e0e`=`e86a88d`), and `git range-diff origin/main..deb origin/main..HEAD` shows only the four intended hotfixes landing on this PR branch.

## Blockers

1. `frontend/src/pages/MapView.tsx:261` hides the `Roads` base layer in public mode, but the selected default can still be `"Roads"` from the local state default (`frontend/src/pages/MapView.tsx:540`) or from config (`frontend/src/pages/MapView.tsx:632`). On a public droplet with the existing/default `map_default_layer` value, `showOsmRoads` is false, so the checked `Roads` base layer is not rendered, while `Map`, `Satellite`, and `Terrain` are all rendered unchecked. React-Leaflet/Leaflet only adds a base layer when its `checked` layer mounts; with no checked mounted base layer, the map can start with radar/markers but no base tiles. This regresses the public map immediately after the OSM fix. Normalize the effective default for public mode, e.g. treat `"Roads"` as `"Map"` when `flags.publicModeActive`, and keep the private behavior unchanged.

## What Needs Attention

None beyond the blocker.

## Bloat / Non-Functional

None. The added test is somewhat verbose, but the extra scaffolding is justified by the exact integration gap that let the wrapped sender payload pass separate sender and endpoint tests.

## Recommendations

- Add a small test or component-level assertion around the public-mode `Roads` fallback if the frontend test harness supports it. If not, the code change should still be straightforward: derive an `effectiveDefaultLayer` inside `BaseLayers` before computing each `checked` prop.
- Keep the StepLocation Carto swap unconditional. Gating that component would preserve the old private-station provider, but it would also keep a known policy-sensitive tile source in a shared component with no functional upside.
