## What Is Correct

- The three requested default-value locations are atomically flipped to `mammoth`:
  - `frontend/src/themes/index.ts:239` exports `defaultTheme = 'mammoth'`.
  - `frontend/src/utils/uiPrefs.ts:18` sets `UI_DEFAULTS.ui_theme` to `"mammoth"`.
  - `backend/app/api/config.py:136` sets `_DEFAULTS["ui_theme"]` to `"mammoth"`.
- `frontend/src/themes/index.ts:229` includes `mammoth` in the `themes` map, so the default key is valid.
- The old localStorage migration map is still intact: `frontend/src/utils/uiPrefs.ts:37-44` keeps `davis-wx-theme` mapped to `ui_theme`, and `_doSync()` still migrates only when the backend is unset or still at the current default. Existing users with saved backend/localStorage theme values should keep their choices.
- I grepped frontend/backend/tests for hardcoded `dark` theme references. I found no remaining first-visit `ui_theme` or `defaultTheme` default that would force dark. The remaining `dark` references are the dark theme module/export, map styling branches for the explicit dark theme, tests/fixtures that intentionally set dark, backend `Settings.theme` for the separate `KANFEI_THEME` setting, and custom-theme editor fallback behavior rather than the first-visit default path.

## Blockers

1. `mammoth.surface.ownsBackground` is still ignored by the shell/background path, so first-visit Mammoth does not reliably render as a paper theme. `frontend/src/themes/mammoth.ts:72-84` marks Mammoth as `ownsBackground: true` and provides the plate/texture, but `frontend/src/context/ThemeContext.tsx:34-82` only applies normal tokens and `--surface-texture`; it never exposes or acts on `ownsBackground`/`plate`. `frontend/src/components/layout/AppShell.tsx:42-80` renders `<WeatherBackground />` solely from the weather-background preference, and that preference still defaults on via `frontend/src/utils/uiPrefs.ts:21`. `frontend/src/components/WeatherBackground.tsx:105-126` likewise treats `enabled` as sufficient: it sets `data-weather-bg="active"`, makes Mammoth card/header/sidebar colors translucent, and renders the gradient/image layers even when the active theme owns the background. For a fresh visitor, the new default theme is Mammoth, `ui_weather_bg_enabled` is true, and the weather layer still composites underneath instead of being replaced by the paper ground/plate. This violates the PR's explicit requirement to confirm `applyThemeToDOM` handles Mammoth's `surface.ownsBackground: true` correctly. The fix should make owned-background themes suppress the weather background/translucency path and render the paper surface/plate on first visit.

## What Needs Attention

None beyond the blocker.

## Bloat / Non-Functional

None.

## Recommendations

- Keep the three `ui_theme`/`defaultTheme` values synchronized as they are now.
- Wire `surface.ownsBackground` into the active background decision. The important behavior is that `enabled === true` must not cause `WeatherBackground` to render or set translucent container CSS variables when the selected theme owns the page background.
- Preserve the existing migration semantics for `davis-wx-theme`; they are not broken by the default flip.
